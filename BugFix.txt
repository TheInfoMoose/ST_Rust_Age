## Root cause: the destination loses track of its own key after Commit

1. **Verify runs before the connection exists.** In [on_verify_remote_token](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/src/main.rs#L1771-L1789), the destination makes a new keypair and tries to save its key ID onto its matching connection entry (`token;my_pub_key`). But that entry isn't created until you press **Commit**, so there's nothing to update and the key ID is thrown away.
2. **Commit saves the plain token.** The Slint Commit button ([main.slint:532](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/ui/main.slint#L532)) passes `token: remote_token.text`, without the `;my_pub_key` suffix. Your saved files confirm it: neither [connections_windows.json](file:///home/zak/DevShare/Simply_Transfer_v2/connections_windows.json) nor [connections_macos.json](file:///home/zak/DevShare/Simply_Transfer_v2/connections_macos.json) has the suffix.
3. **The heartbeat then looks up the wrong key.** At [main.rs:285](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/src/main.rs#L285), `key_to_use = my_pub_key.unwrap_or(&parsed.pub_key)` falls back to the **source's** public key. The destination's keyring has no private key for that, so `get_private_key_pem` fails and no SSH login is even attempted. Port 22 is open, so the state lands on "Pending Verification" and retries every 5 seconds without ever succeeding.

**Why transfers still work:** `start_transfer` has a fallback to `~/.ssh/simply-transfer-remote.pem` ([main.rs:494-498](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/src/main.rs#L494-L498)). The heartbeat has no such fallback, so the connection is healthy but the state tracker can't see it.

**Why it seems to appear later:** Commit hard-codes `state: "Connected"`, and the heartbeat skips connections in that state ([main.rs:241](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/src/main.rs#L241)). After any restart, every connection is reset to `"Checking..."` ([main.rs:209](file:///home/zak/DevShare/Simply_Transfer_v2/simply-transfer-ui/src/main.rs#L209)), the heartbeat takes over, and it gets stuck.

## Proposed fix (needs your approval)

1. **Keep the key ID through Commit.** After a successful Verify, store `token;my_pub_key` in a Slint property and have Commit use it instead of `remote_token.text`.
2. **Fix the heartbeat:** probe port 2222, report `"Connected"` on success, and add the same `.pem` fallback that `start_transfer` uses.
3. **Optional:** save the P2P daemon's accepted keys to disk and reload them at startup (C), add a read timeout to the handshake (E), and name the key file per peer (D).
